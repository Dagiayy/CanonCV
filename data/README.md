# Application data

Everything in this folder is **generated by the app at runtime** — none of it
is version-controlled (see root `.gitignore`). It's safe to delete this
folder's contents entirely; the backend recreates the subfolders it needs on
startup, and `app.db` (SQLite) rebuilds fresh via `python -m app.seed`.

This is `DATA_DIR` — override its location with the `DATA_DIR` environment
variable if you want it somewhere else (see `backend/app/config.py`).

| Path | What it is |
|---|---|
| `app.db` | SQLite database — projects, taxonomy versions, datasets, mapping tables, runs, split plans, exports. |
| `normalized/` | Canonical YOLO-format output from normalization runs. |
| `mapping_tables/` | Every "ready" mapping table, exported as git-trackable YAML for review (per source-label → canonical-class decisions). |
| `review_queue_crops/` | Thumbnail crops for labels routed to manual review during a normalization run. |
| `exports/` | Immutable versioned export snapshots (train/val/test splits + `data.yaml` + lineage `manifest.json`). |
| `class_stats.json` | Per-canonical-class instance counts, generated on demand via `python -m app.generate_reports`. |
| `data_card.md` | Provenance/license table per source dataset, generated the same way. |

## Resetting to a clean state

```bash
rm -rf data/*
docker compose exec backend python -m app.seed   # or run bare-metal equivalent
```

This does **not** touch `normalization datases/` — raw source datasets are
untouched by anything in this app; only this folder (derived/generated state)
is ever written to by the backend.
